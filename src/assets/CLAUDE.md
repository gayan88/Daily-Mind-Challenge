# src/assets

`images/` holds every real image file the app uses: the logo (`logo.png`/`logo-header.png`/`Full Logo.png`), the four game tile images (`tile-wordle.png`/`tile-sudoku.png`/`tile-wordsearch.png`/`tile-connections.png`, 400x400, see `docs/adding-a-new-game.md`), and the Rank badge set: `rank-novice.png` through `rank-legend.png` plus `rank-guest.png` (400x400, the *generic per-tier* badges — used for the "All Ranks" strip and the hero progress bar's flanking main-rank icons, see `src/js/progression/rank-service.js`), and `sub-ranks/` — 100 smaller (200x200) images, `{rankName}-{1..10}.png` (e.g. `sub-ranks/novice-7.png`), one per exact "{Rank} {Numeral}" combination, cropped from a separate user-supplied 10x10 reference sheet. These are what the profile page's avatar actually shows (the player's *exact* sub-rank, not just their coarser tier) — see `rank-service.js#subRankImagePath()`. All referenced by root-relative `/assets/images/...` paths, per `src/html/CLAUDE.md`'s convention.

`images/home-tile-{game}.png` (400×320, white, one per game) are the **home page grid's** tiles only (`index.html`), made 2026-10-21 so all six look the same size: each logo trimmed, near-white turned pure white (no faint grey boxes), and scaled to the same visual area. Wordle/Sudoku/Word Search/Connections are cut from their `tile-*.png`; Quilt and Pounce from the owner's full-size logos. The square `tile-*.png` stay as they were for profile cards and How to Play banners. A new game needs a matching `home-tile-*.png` (same canvas and sizing).

`images/achievements/` holds the 121 achievement badge PNGs (67 + Connections' 18 + Quilt's 18 + Pounce's 18) (240x240, transparent, named `{achievementId}.png`, wired via `CUSTOM_IMAGES` in `progression/achievement-registry.js` -- every achievement now has custom art, no emoji fallback in use); `images/New/` keeps the full-resolution originals (~1254x1254) renamed to the same ids -- when new art is uploaded there under auto-generated names, identify each, MD5-check for duplicates, process into `achievements/`, then rename the original. Quilt's 18 originals (1312×1199, several with a fake checkerboard/white background baked into the pixels) were renamed to their ids in place in `docs/Images/` (removed from there 2026-10-20; recover with `git checkout 63db3be^ -- docs/Images`); the 240×240 copies here had that background removed (light, low-colour pixels connected to the image border, plus speckle cleanup) before resizing. `tile-quilt.png` (400x400) and `tile-quilt-wide.png` (500x384, the full-width fifth home tile) are cut from the owner's Quilt logo (`docs/Images/QUILT Logo.png`, now only in git history) and are the real tile art; `quilt.html` also uses the wide one as its og:image, which *is* still a stand-in until a purpose-made 1.91:1 share image exists. Pounce's 18 badge originals are already transparent, named by id, in `docs/Images/` (white background removed there); the 240×240 copies here are contain-fit resizes. `tile-pounce.png` (400x400) and `tile-pounce-wide.png` (500x384, used on the home grid) are cut from the owner's logo (`docs/Images/Playful Pounce Cat Puzzle Logo.png`), and `fb-share-pounce.png` (1756x896) is that logo on white, a stand-in og:image until a purpose-made share image exists. `fb-share-connections.png` (1756x896) is Connections' social-share image, like the other `fb-share-*.png`. `src/404.html`, `robots.txt`, `sitemap.xml` and `ads.txt` live at the `src/` root, not here.

Icons/emblems that *aren't* rank badges or tile art are still plain Unicode emoji, centralized in `src/js/utils/icons.js` and rendered via `textContent` (see that file's comments for why: a bad copy/paste of raw emoji glyphs into HTML previously produced mojibake, so emoji only ever live as explicit `\u{...}` escapes in one JS file). Don't add a new image file for something an emoji already covers well — `icons.js` is still the first place to look before reaching for a graphic.

No `icons/` subfolder exists yet — if SVG icon files are ever needed (as opposed to emoji or the photo-style badges in `images/`), that's where they'd go.
