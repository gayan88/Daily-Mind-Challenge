# src/js/admin

Everything here is gated on `profile.isAdmin` — `admin-page.js` redirects non-admins away immediately. `src/html/admin.html` is the only page that loads this folder's code.

## Files

- **`moderation.js`** — direct Firestore operations restricted to admins by security rules: `lookupUserByUsername()`, `setUserBanned()`/`setUserAdmin()` (toggle a `registeredUsers` doc's moderation fields).
- **`wordle-admin.js`** — Firestore layer for Wordle admin features. Daily Challenge word pool: `listDailyWords()`, `addDailyWord()` (append-only — writes the next numeric id and bumps `wordleDailyWords/_meta.totalCount`, which `src/js/games/wordle/wordle-daily-data.js#getTodayChallenge()` reads to resolve today's word), `updateDailyWord(id, word)` (corrects a word's text without changing its position, since position determines which date it lands on). Tournaments: `listTournaments()`, `createTournament({ name, words, timePerWordSeconds, bonusPoints })` (active by default), `setTournamentActive(id, active)` (deactivate without deleting history), `deleteTournament(id)`.
- **`sudoku-admin.js`** — Firestore layer for Sudoku admin features, mirroring `wordle-admin.js`'s shape. Daily pool: `listDailySudokuPuzzles()`, `addDailySudokuPuzzle(puzzle, solution)` (append-only, next numeric id, bumps `sudokuDailyPuzzles/_meta.totalCount`), `updateDailySudokuPuzzle(id, puzzle, solution)`. Classic pool: same three functions plus a `difficulty` ('easy'/'medium'/'hard') argument, sharing one numeric id counter across all three difficulties. Tournaments: `listSudokuTournaments()`, `createSudokuTournament({ name, puzzles, completionBonus })` (active by default; `puzzles` is an array of `{ puzzle, solution }` pairs; `completionBonus` is set per tournament, unlike the time limit/max errors which stay global via `config/sudokuTournamentSettings`), `setSudokuTournamentActive()`, `deleteSudokuTournament()`. `validateSudokuPuzzlePair(puzzle, solution)` runs before every puzzle write (Daily, Classic, and each puzzle in a Tournament create) — checks both strings are 81 characters, the solution is a valid completed grid (every row/column/3x3 box has each digit 1-9 exactly once), and the puzzle's given cells match the solution — since there's no way to hand-verify an 81-character string visually.
- **`wordsearch-admin.js`** — Firestore layer for Word Search admin features, mirroring `sudoku-admin.js`'s shape. Daily pool: `listDailyWordsearchPuzzles()`, `addDailyWordsearchPuzzle({ theme, words })` (append-only, next numeric id, bumps `wordsearchDailyPuzzles/_meta.totalCount`), `updateDailyWordsearchPuzzle(id, { theme, words })`. Classic pool: same three functions plus a `difficulty` argument, sharing one numeric id counter across all three difficulties. Tournaments: `listWordsearchTournaments()`, `createWordsearchTournament({ name, puzzles, completionBonus })` (`puzzles` is an array of `{ words }` entries; `completionBonus` is set per tournament, unlike puzzle count/time limit/completed-and-failed-puzzle points, which stay global via `config/wordsearchTournamentSettings`), `setWordsearchTournamentActive()`, `deleteWordsearchTournament()`. `validateWordList(words, { minCount, maxCount })` runs before every word-list write — checks the count matches the mode's requirement (`src/js/games/wordsearch/wordsearch-modes.js` is the single source of truth for these numbers), every word is alphabetic and 4-9 letters, and **no word is a substring of another word in the same list** (case-insensitive, either direction) — this last check is a genuine correctness requirement, not a nicety: the engine's selection matching checks both the forward and reversed letter string against every remaining word, so a substring pair like "CAT"/"CATFISH" would make one drag ambiguously satisfy two words.
- **`admin-page.js`** — page glue for `src/html/admin.html`. Content is organized into five collapsible top-level sections: **General** (Platform Config forms — `dailyLoginReward`, `challengeExpiration`, `myChallengesPageSize`, `browseChallengesPageSize`, `leaderboardPageSize`, `challengeAttemptsPageSize`, `sudokuTournamentSettings`, `wordsearchTournamentSettings`, `wordValidationAPI`, `profanityList`, each seeded with defaults on first load via `ensureConfigDefaults()` — plus Moderate Users), **Advertisements** (the 3 home-page ad slots, plus a "Game wise" subsection with a nested collapsible per game — Wordle/Sudoku/Word Search — each showing that game's top/bottom ad slots), **Wordle** (a Daily Words table — add/edit only — plus a Tournaments table + create form, both via `wordle-admin.js`), **Sudoku** (Daily Puzzles and Classic Puzzles tables — add/edit only, via `sudoku-admin.js` — plus a Tournaments table + create form taking a name and two newline-separated textareas, puzzles and solutions, paired by line index), and **Word Search** (Daily Puzzles and Classic Puzzles tables — theme + words textarea, add/edit only, via `wordsearch-admin.js` — plus a Tournaments table + create form taking a name and one newline-separated textarea where each line is one puzzle's comma-separated word list). Word Search's admin tables reuse Sudoku's generic `.sudoku-daily-row`/`.sudoku-puzzle-form` CSS classes as-is rather than cloning parallel `.wordsearch-*` versions — already game-agnostic layout, same reuse precedent as `.tournament-row`/`.status-pill` being shared across all three games' admin tables. This grouping exists purely to keep the page scannable; it has no bearing on the data model.
  - `renderConfigForms()`'s generic form renderer wraps each field in a `.config-form-field` div with its own `<label>` (built from each `CONFIG_FORMS` entry's `field.label`) — this only became visually necessary once `sudokuTournamentSettings` introduced the first 4-field config form; every earlier form had exactly one field, where the form's own title/description already made a separate label redundant.

The collapsibles are plain `<div data-collapsible>` + `<button>` (see `wireCollapsibleSections()`), **not** `<details>`/`<summary>` — `<details>` was tried first but its box width behaved inconsistently between open/closed states across at least one browser, which a `<details>`-based fix couldn't reliably override. The current approach toggles an `.open` class via a click handler, and CSS shows/hides the inner content with plain `display: none`/`block`, which can never affect the outer box's own width (already fixed at `width: 100%; max-width: var(--content-max-width)`).

## Ad slots

`config/ads` holds per-slot settings for all 9 ad placements across the site (`src/js/utils/ads.js#AD_SLOTS` is the canonical list — id, label, and a `group` used only to sort slots into the admin panel's sections above). Each slot has `enabled` (hide it entirely when off), `type` (`'google'` shows the existing static AdSense-placeholder markup already in the HTML — there's still no real AdSense integration, just an honest placeholder — while `'image'` rewrites the slot into a clickable image ad using `imageUrl`/`linkUrl`), and those two URL fields. `admin-page.js#renderAdSlotForms()` renders each group into its own container (`ad-slot-forms-home`/`-wordle`/`-sudoku`/`-wordsearch`) but all four share one in-memory `slots` object — saving any single slot's form re-reads/merges that shared map before writing the whole `config/ads` doc back, so editing e.g. a Wordle ad from the "Game wise" subsection never clobbers the Home ads. The actual per-page rendering happens automatically on every page load via `applyAdSlots()`, called from `src/js/app.js#loadHeaderFooter()` — admin-page.js only edits the settings, it doesn't render the ads itself.

## Bootstrapping the first admin

No code path can safely auto-grant admin — see the root `README.md` for the one-time manual step (sign up normally, then flip `isAdmin: true` on that account's `registeredUsers` doc via the Firebase console).

## Not implemented

There's no analytics panel and no pre-computed/scheduled jobs (no Cloud Functions in this app at all).

## Word validation

`config/wordValidationAPI.endpoint` (editable here, defaults to the Free Dictionary API's `v2` endpoint — **not** `v1`, which returns `502` instead of `404` for a nonexistent word, making "not a real word" indistinguishable from "the API is down") backs `src/js/games/wordle/wordle-word-validation.js#isRealWord()`, used both to reject non-dictionary words when creating a Challenge a Friend and live during play across all three Wordle modes (every guess that isn't the exact target word gets checked before it's accepted). It fails *open* — any non-404 response, a 5s timeout, or a network error all let the word/guess through rather than blocking play or challenge creation on a flaky third party. Not wired into Daily Words or Tournament word entry in this section — an admin can still seed a nonsense "word" there without complaint.
