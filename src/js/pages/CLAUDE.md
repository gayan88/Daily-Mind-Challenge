# src/js/pages

Page-glue scripts for pages that don't have a dedicated feature folder of their own (compare `src/js/games/*`, `src/js/leaderboard/`, `src/js/admin/`, which keep their page script colocated with their feature's other files instead of living here).

## Files

- **`home.js`** — the busiest file in the app. Loaded by `src/html/index.html`, which doubles as both the landing page (dashboard: status card, game tiles, leaderboard preview — all rendered from public data even for logged-out visitors) **and** the sign-in surface (there is no separate login page). If there's no session, it renders a generic dashboard and wires up the header's Login button to open the inline Guest/Log In/Sign Up modal. Game tiles are plain `<a href>` links regardless of session state -- they used to be intercepted for logged-out visitors (opening the sign-in modal directly instead of navigating, since every game page required a session at the time), but now that `wordle.html`/`sudoku.html`/`wordsearch.html` render real content for anonymous visitors too (see their own `trySession()` usage, `src/js/CLAUDE.md`), that interception would have blocked exactly the navigation that should now be allowed, so it was removed.
  - **Phase 8 ("Daily Brain Workout")**: for registered players, the status card also shows streak + Overall Level/XP (`progression/xp-service.js#calculateOverallProgress()`) and a workout-completion hint that reuses Phase 3's real `XP_AMOUNTS.PERFECT_DAY_BONUS` value rather than the spec mockup's own "+100 XP" -- that number would have been a second, conflicting "finish everything today" bonus on top of the one already built; see `docs/progression-gamification-roadmap.md`'s Phase 8 section for the decision. A new compact "Daily Missions: N/3 complete" / "N badges earned" strip (`renderWorkoutExtras()`) links out to `/profile` for full detail rather than duplicating those sections here -- an explicit "compact summary, not full rebuild" scope decision. `renderLoggedInDashboard()` calls `progression/mission-service.js#syncDailyMissions()` itself (registered players only) -- the home page, not just `/profile`, is treated as a legitimate place for "did I finish today's workout" to actually resolve and award XP, since it's the page the spec envisions as the daily-return destination; safe to call from both pages since it's idempotent. Achievements are only **read** here (a plain count via `achievement-engine.js#getPlayerAchievements()`), never re-evaluated -- that heavier context-assembly stays exclusive to `profile.js`, keeping this page's Firestore work light.
- **`profile.js`** — a 2-column hero layout (`profile-hero-layout`, stacks to 1 column below 768px). **Left column**: avatar (a Rank badge image via `progression/rank-service.js#calculateRankProgress()`/`GUEST_RANK_IMAGE`, shown for guests too as a fixed distinct badge rather than defaulting them into "Novice"), display name, a tagline that shows the current rank label (e.g. "Novice VII") for registered players or the original static "Play daily..." copy for guests, and for registered players only: streak (visual-only milestone highlight at 7/30/100/365 days via `progression/streak-service.js#getStreakMilestoneTier()`, Phase 4) and a progress bar toward the **next main rank** (10,000 XP wide) -- an "Edit Profile" button toggles the display-name field/Save button, which used to always be visible. **Right column** (registered only): the "Rank Progression" panel -- Current Rank / Next Rank boxes showing **sub-rank**-level progress (1,000 XP wide, deliberately the complementary granularity to the hero's main-rank bar, not a duplicate), and a "🏆 Ranks List" button that toggles the full 10-tier ladder (built generically from `rank-service.js#MAIN_RANKS`, current tier highlighted) open/closed -- previously a hover-only "How it works?" tooltip. Below both columns: a 4-tile stat row (Total Points, Total XP, Games Played, and Achievements -- a count of *all* distinct achievements earned, any category, replacing an earlier narrower "Games mastered" `category: 'game'`-only count) with icon-circle styling; guests get a 2-tile row (Total Points, Games Played only). Below that: a per-game "Your Games" section (logo, Points, and for registered players only, Level/progress/modes-played -- via `progression/progression-service.js#getGameProgressByGame()`, Phases 1-2), a "Today's Missions" section (Phase 7 -- each of `progression/mission-service.js#DAILY_MISSIONS` with its live `current/target` progress and XP reward, from `syncDailyMissions()`), an "Achievements" section (every definition from `progression/achievement-registry.js#ACHIEVEMENTS`, earned ones highlighted with a "×N" count for accumulating ones and unearned ones shown locked with their real condition), and recent game history. `init()` calls these progression syncs in a specific order -- `claimChampionshipAchievements()` (Phase 6), then `syncDailyMissions()` (Phase 7), then `syncPlayerAchievements()` (Phase 5) -- so a championship win or mission reward claimed just now shows up in the very same render rather than only on the next visit; `renderHero()` is deliberately called *after* all of these, so its rank/tagline reflect any XP a mission/login bonus just awarded this visit. Guests can view but not rename themselves here (settings-style edits are registered-only) and still see their real per-game Points (guests do earn Points), but rank/progress/streak/XP/Achievements/Missions are gated to registered players -- these are all registered-player concepts per Section 4 of the progression spec, so a guest sees a locked placeholder plus a sign-up note instead.
- **`settings.js`** — registered-users-only (redirects/blocks guests entirely, matching the "guests have no settings page" rule). Display name, recovery email, and password change.

## Retired: the generic "Challenges" feature

`challenges.html`/`challenges.js`/`challenges-data.js` and the `challenges` Firestore collection have been removed — that feature only ever supported Wordle, and Wordle now has its own richer "Challenge a Friend" mode built directly into `wordle.html` (see `src/js/games/wordle/CLAUDE.md`). The nav/footer "Challenges" links and the home page's "Open challenges" preview section were removed along with it.
