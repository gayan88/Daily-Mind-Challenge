# src/js/pages

Page-glue scripts for pages that don't have a dedicated feature folder of their own (compare `src/js/games/*`, `src/js/leaderboard/`, `src/js/admin/`, which keep their page script colocated with their feature's other files instead of living here).

## Files

- **`home.js`** — the busiest file in the app. Loaded by `src/html/index.html`, which doubles as both the landing page (dashboard: status card, game tiles, leaderboard preview — all rendered from public data even for logged-out visitors) **and** the sign-in surface (there is no separate login page). If there's no session, it renders a generic dashboard and wires up the header's Login button to open the inline Guest/Log In/Sign Up modal. Game tiles are plain `<a href>` links regardless of session state -- they used to be intercepted for logged-out visitors (opening the sign-in modal directly instead of navigating, since every game page required a session at the time), but now that `wordle.html`/`sudoku.html`/`wordsearch.html` render real content for anonymous visitors too (see their own `trySession()` usage, `src/js/CLAUDE.md`), that interception would have blocked exactly the navigation that should now be allowed, so it was removed.
  - **Phase 8 ("Daily Brain Workout")**: for registered players, `renderStatusCard()`'s header (`.status-top-row`) is a two-column layout -- left column: the sub-rank avatar (`calculateRankProgress(xp).subRankImage`, same badge/color source `leaderboard/player-profile-modal.js` and every leaderboard row use) + the display name alone (the "Welcome back," prefix was dropped so long names like a full first+last name don't wrap or crowd the Level card at 28px bold) + rank label + a "🔥 N day streak · ⭐ X Total XP" line right under the rank label; right column: a `.status-level-card` (Level `N+1`, `xpIntoLevel / XP_PER_LEVEL` XP, a progress bar, "X XP to reach Level N+2" caption -- same shape and same `+1` display convention as `leaderboard/player-profile-modal.js`'s own Level card, both built off `progression/xp-service.js#calculateOverallProgress()`'s `xpIntoLevel` field and exported `XP_PER_LEVEL` constant rather than a hardcoded number). Guests get the fixed `GUEST_RANK_IMAGE` avatar and skip the streak/XP line and the Level card entirely (Section 4 -- guests don't earn either). There is deliberately **no** workout-completion hint text anymore (an earlier "Complete every game today for a bonus" / "Today's workout complete!" line, reusing Phase 3's `XP_AMOUNTS.PERFECT_DAY_BONUS`, was removed outright at the user's request rather than reworded) -- `awardDailyCompletionXp()`/`advanceStreakForDailyCompletion()` still fire from each game's own Daily Challenge completion handler exactly as before, this page just no longer echoes a hint about it.

    Below the status card, `renderWorkoutExtras()` renders two full-width cards side by side (`.workout-extras-grid`, stacking under 700px) -- "Daily Missions" (icon, title, subtitle, a big "N/5 completed" stat, its own progress bar) and "Achievements" (icon, title, subtitle, a big "N badges earned" stat, no progress bar -- there's no natural "target" for a running badge count) -- each ending in a pill-styled "View →" button linking to `/profile` for full detail, rather than duplicating those sections here (an explicit "compact summary, not full rebuild" scope decision carried over from the original, plainer version of this section). `renderLoggedInDashboard()` calls `progression/mission-service.js#syncDailyMissions()` itself (registered players only) -- the home page, not just `/profile`, is treated as a legitimate place for "did I finish today's workout" to actually resolve and award XP, since it's the page the spec envisions as the daily-return destination; safe to call from both pages since it's idempotent. Achievements are only **read** here (a plain count via `achievement-engine.js#getPlayerAchievements()`), never re-evaluated -- that heavier context-assembly stays exclusive to `profile.js`, keeping this page's Firestore work light.
  - **Leaderboard preview** (`renderLeaderboardPreview()`, the top-5 "Today's Leaderboard" section): each row now shows that player's sub-rank avatar too (`avatarsForRows()`, batched via `leaderboard/leaderboard-data.js#getXpForUids()` -- only for the 5 rows actually rendered, never the full leaderboard) and is clickable, opening `leaderboard/player-profile-modal.js#showPlayerProfileModal()` for that player -- same click-to-open behavior as the main Leaderboard page's own rows, via one delegated listener wired once (`el.dataset.clickWired` guard) against a `previewRowsByUid` map that's refreshed on every render so the listener always resolves against whatever's currently on screen.
- **`profile.js`** — a single-column card layout (a 2-column hero+side-panel layout was tried first but abandoned for excess white space -- see `src/css/pages/profile.css`'s own history comment). `renderHero()`: avatar is now the player's exact **sub-rank** badge (`calculateRankProgress(xp).subRankImage`, one of the 100 images at `src/assets/images/sub-ranks/`, not the old generic per-tier `MAIN_RANKS[].image`) or `GUEST_RANK_IMAGE` for guests -- a small pencil icon button (`#edit-profile-btn`) opens an Edit Profile **modal** (`.modal-overlay`/`.modal-dialog`, shared with `home.html`'s sign-in modal via `components.css`) to change the display name, replacing an earlier always-visible inline field. The tagline shows the current rank label (e.g. "Novice VII") for registered players, the guest's static "Play daily..." copy otherwise. `renderRankCard()`: a single wide progress bar toward the **next main rank** (10,000 XP wide), flanked by the current and next-sub-rank badge icons (`subRankImage`/`nextSubRankImage`) on either side, with the big "X / 1,000 XP" sub-rank number and caption centered under it. `renderRankPanel()`: a horizontal "All Ranks" strip (`rank-strip`, built generically from `rank-service.js#MAIN_RANKS`) with a custom CSS tooltip per icon (`data-tooltip` + `::after`, not the native `title` attribute -- that didn't reliably show text across browsers) and the current tier visually marked; hidden until the strip is present, always visible now rather than toggled by a button. `renderStats()`: a 4-tile stat row (Total Points, Total XP, Games Played, Achievements -- a count of *all* distinct achievements earned, any category) with icon-circle styling; guests get a 2-tile row (Total Points, Games Played only).

  `renderGameProgress()` ("Your Games" section, via `progression/progression-service.js#getGameProgressByGame()`): cards sorted by lifetime Points descending, each a large branded game logo (~96px, shrinking to 64px under 380px) beside a body column (name + **Level** chip, Points, progress bar, "Points to next Level" caption, mode chips) -- `Level` in this card is `g.level + 1`, a **display-only** +1 shift so a brand-new player sees "Level 1" instead of "Level 0"; the underlying `level` field from `progression-service.js` stays 0-indexed everywhere else (achievement thresholds read that raw number, see `progression/CLAUDE.md`'s achievement-registry.js entry). Paginated 3 at a time via "Load More" (`GAMES_PAGE_SIZE`), matching `leaderboard-page.js`'s pagination pattern -- the button only appears once there are more than 3 games.

  `renderMissions()` ("Today's Missions", via `progression/mission-service.js#DAILY_MISSIONS`): a responsive card grid (1/2/3 columns), each card a colored icon circle (cycling through 5 tint variants) + title/XP-reward pill on one row, a big "current / target" number, and its own progress bar underneath -- replacing an earlier plain vertical list.

  `renderAchievements()`: every definition from `progression/achievement-registry.js#ACHIEVEMENTS` (67 total), grouped by *status* -- Completed / In Progress / Not Started -- rather than by category, per a user-supplied mockup: scales better than a flat grid as the registry grows (Championships alone are 45 of 67), and surfaces what's actually actionable instead of mixing earned and locked together. A summary bar up top shows "N / 67 Achievements Unlocked". Completed and Not Started render as compact icon strips with a hover tooltip per icon (same custom-CSS-tooltip mechanism as the "All Ranks" strip above -- native `title` tooltips don't reliably show text), each icon either that achievement's `CUSTOM_IMAGES` badge art (`src/assets/images/achievements/`, Wordle-only currently) or its category's plain emoji, grayscaled via CSS when locked rather than a generic lock icon, so a Not Started item still hints at *what* it is. In Progress renders full detail rows (icon, label, description, a live "current / target" number and bar), sorted furthest-along-first, using each achievement's own `progress()`/`target` (see `achievement-registry.js`'s own doc comment for which entries have one at all) -- **but only for the lowest-order not-yet-earned member of each tiered `family`** (Level tiers, Streak tiers, Championship tiers, the "all 3 games" tiers); every other unearned sibling in that family is forced into Not Started instead, even though its own `progress()` would technically be > 0, since they all share one underlying number (e.g. Wordle Daily Champion's 30/50/100-times tiers all reading the same win tally) and only the next tier actually up for grabs should read as actionable. This pre-computation (`byFamily`/`familyNextUnearned` maps) happens once per render, before the main bucketing pass. Every achievement is create-once now (no more accumulating "×N" count anywhere, including Championships -- see `progression/championship-service.js`'s tiered-badge design), so earned/unearned is a plain lookup. `init()` calls the progression syncs in a specific order -- `claimChampionshipAchievements()`, then `syncDailyMissions()`, then `syncPlayerAchievements()` -- so a championship win or mission reward claimed just now shows up in the very same render rather than only on the next visit; `renderHero()` is deliberately called *after* all of these, so its rank/tagline reflect any XP a mission/login bonus just awarded this visit. Guests can view but not rename themselves here (settings-style edits are registered-only) and still see their real per-game Points (guests do earn Points), but rank/progress/streak/XP/Achievements/Missions are gated to registered players -- these are all registered-player concepts per Section 4 of the progression spec, so a guest sees a locked placeholder plus a sign-up note instead.
- **`settings.js`** — registered-users-only (redirects/blocks guests entirely, matching the "guests have no settings page" rule). Display name, recovery email, and password change.

## Retired: the generic "Challenges" feature

`challenges.html`/`challenges.js`/`challenges-data.js` and the `challenges` Firestore collection have been removed — that feature only ever supported Wordle, and Wordle now has its own richer "Challenge a Friend" mode built directly into `wordle.html` (see `src/js/games/wordle/CLAUDE.md`). The nav/footer "Challenges" links and the home page's "Open challenges" preview section were removed along with it.
