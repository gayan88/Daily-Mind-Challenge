# src/js/games/wordle

`wordle.html` has three modes, selected by a tab row: **Daily Challenge**, **Tournaments**, and
**Challenge a Friend** (internally still "wordleChallenges"/`wordle-challenge-data.js` in code and
schema — only the user-facing label changed). All three are live.

## Files

- **`wordle-engine.js`** — the playable game itself, mode-agnostic: `playWordleRound({ container, targetWord, maxGuesses, timeLimitSeconds, validateGuess, onComplete })` builds the board + on-screen/physical keyboard into `container`, handles guess evaluation (two-pass duplicate-letter-safe algorithm), and calls `onComplete({ won, attempts, guessStates, timedOut })` once. `guessStates` is the per-guess correct/present/absent array for every submitted row, used by `wordle-summary-modal.js` to render the colored-square grid. `timeLimitSeconds` is optional — when set, shows a visible countdown and ends the round as a timed-out loss if it hits zero (used by Tournament mode). `validateGuess` is an optional `async (guess) => boolean` -- when set (all three modes pass `wordle-word-validation.js#isRealWord`), every non-target guess is checked before being accepted; the row shows "Checking word…" while awaiting it, input is locked for the duration (`submitting` guard), and the guess is snapshotted before the `await` so an in-flight check can never be applied to a guess the player has since edited, or to a round that ended out from under it (e.g. a tournament timer hitting zero mid-check -- re-checked via `gameOver` right after the `await` resolves). The exact target word always bypasses the check, since the win condition shouldn't depend on the dictionary API recognizing whatever word an admin/creator picked. The engine itself has no opinion on *how* validation decides and no Firebase/session knowledge at all — shared by all three of `wordle.html`'s own modes.
- **`wordle-word-validation.js`** — `isRealWord(word)`, checked against `config/wordValidationAPI.endpoint` (the Free Dictionary API `v2`, **not** `v1` — `v1` returns `502` instead of `404` for a nonexistent word, making "not a real word" indistinguishable from "the API is down"). Fails *open*: any non-404 response, a timeout (5s, via `AbortSignal.timeout`), or a network error all count as valid, so a flaky third party can never fully block either playing or creating a challenge. Used at Challenge a Friend creation time (`wordle-challenge-data.js#createWordleChallenge()`) and live during play via the engine's `validateGuess` above -- kept in its own file since it's no longer just a challenge-creation concern. Not wired into Daily Words or Tournament word entry in the admin panel.
- **`wordle-page.js`** — page glue for `wordle.html`: `initShell()`, blocks admins from playing, then wires the three mode tabs (`wireModeTabs`). **Daily Challenge** (`renderDailyMode`) gates on `checkPlayedToday(uid, 'wordle')`, resolves today's word via `wordle-daily-data.js#getTodayChallenge()`, mounts the engine, and on completion calls `recordDailyResult()` then shows `wordle-summary-modal.js`. **Tournaments** (`renderTournamentsMode` / `playTournamentRound`) lists active tournaments with each one's Start/Continue/Completed status, plays the player's current word with a countdown, and on a loss resets progress and offers a retry; on the final word's win it calls `finalizeTournament()` and shows the summary modal. **Challenge a Friend** (`renderChallengeMode` and friends) has three sub-tabs — Browse (public, non-expired, excluding your own, paginated `config/browseChallengesPageSize.size` at a time via "Load More" -- if a fetched page comes back entirely filtered out, `loadPage()` silently fetches the next one instead of showing an empty page with nothing on it), Create (registered users only; 5-letter word, checked against `config/wordValidationAPI` for being a real word — see `wordle-challenge-data.js#isRealWord()` — plus public/private visibility, produces a `wordle.html?challenge={id}` share link), My Challenges (your own challenges as compact cards -- `#N`, word, creation date, attempt count, visibility -- paginated `config/myChallengesPageSize.size` at a time; opening this view also runs `syncCreatorRewards()` over *all* of your challenges regardless of how many are currently paginated in, see below). Each My Challenges card's "More Info" button (`wireMineDetailToggle()`) lazily expands into a detail panel -- nothing about that challenge's attempts is fetched until the card is actually opened -- with the share-link box and an Attempts table (`#`, user, `attempts/6`, Solved/Failed pill), itself paginated `config/challengeAttemptsPageSize.size` at a time via its own "Load More". Toggling the card closed and back open again doesn't re-fetch. Plus a deep-link path: loading `wordle.html?challenge={id}` jumps straight to solving that one challenge instead of showing the sub-tabs, so a shared link works standalone.
- **`wordle-daily-data.js`** — Firestore layer for Daily Challenge: `getTodayChallenge()` (resolves the numbered word for today, `(daysSinceEpoch(date) % totalCount) + 1`, from the admin-managed `wordleDailyWords` collection — see `src/js/admin/wordle-admin.js`), `recordDailyResult()` (writes the points formula below to `gameScores` with the existing `{uid}_wordle_{date}` deterministic ID, so a repeat attempt is rejected the same way every other game's score is), `markSharedToFacebook()` (one-time guarded +20, applied as a Firestore `update` after the score doc already exists — see `firestore.rules`' `isFacebookShareUpdate()`).
- **`wordle-tournament-data.js`** — Firestore layer for Tournaments: `listActiveTournaments()`, `getAttempt()` / `getOrStartAttempt()` (one progress doc per player per tournament, id `{tournamentId}_{uid}`, created at word 1 on first play), `recordWordResult(tournamentId, uid, won)` (advances `currentWordIndex`/`wordsWon` on a win, resets both to 0 on a loss — players can retry a failed tournament indefinitely, but a failed run banks nothing), `finalizeTournament()` (one-shot award of `30 + 15*numWords + bonusPoints` to `gameScores` under `gameType: 'wordle-tournament'` with a deterministic `{uid}_wordle-tournament_{tournamentId}` id — the same create-only guarantee as every other game score means this can never double-pay even if called twice — then flips the attempt's `completed` flag permanently).
- **`wordle-challenge-data.js`** — Firestore layer for Challenge a Friend, in the `wordleChallenges` collection (`{ creatorUid, creatorDisplayName, word, visibility, challengeNumber, createdAt, expiresAt }`, with a `completions/{uid}` subcollection per challenge). `challengeNumber` is a global, continuously-incrementing counter (not per-creator, so "Oshini's Challenge #1"/"#2" are distinguishable even with duplicate creator names) tracked in `wordleChallenges/_meta.totalCount` and bumped inside the same transaction that creates the challenge — same pattern as the Daily Challenge word pool, just writable by any registered user instead of admin-only. `createWordleChallenge()` (registered users only; expiry reuses `config/challengeExpiration`; the word must pass `isRealWord()`, a dictionary check against `config/wordValidationAPI.endpoint` that fails open on any API error so a flaky third party can't block challenge creation entirely), `listPublicWordleChallengesPage(pageSize, cursor)` / `listMyWordleChallengesPage(uid, pageSize, cursor)` (both cursored via `startAfter`, for rendering Browse/My Challenges a page at a time -- reuse the existing `(visibility, createdAt)` / `(creatorUid, createdAt)` composite indexes, no new indexes needed), `listWordleChallengeCompletionsPage(challengeId, pageSize, cursor)` (cursored via `startAfter` on `completedAt`, for one challenge's Attempts table -- only needs Firestore's automatic single-field index, no composite), `listMyWordleChallenges(uid)` (unpaginated, for `syncCreatorRewards()` only), `getWordleChallenge()` / `getWordleChallengeCompletion()` / `getWordleChallengeSolveCount()` (a `getCountFromServer` aggregation query counting only `won == true` — Browse cards show "N people solved it") / `getWordleChallengeAttemptCount()` (same aggregation shape but no `won` filter — My Challenges cards show "N Attempts"), `recordWordleChallengeCompletion()` (player's own `10 + 20-if-won` score), and `syncCreatorRewards()` (see Points below for why this is separate).
- **`wordle-summary-modal.js`** — shared post-round popup (points breakdown, colored-square attempt grid built from `guessStates` when provided, Facebook share button using the same `sharer.php` popup pattern as the footer share in `src/js/app.js`). Builds its own DOM into `document.body`; no markup for it lives in `wordle.html` itself. Used by Daily Challenge, Tournaments, and Challenge a Friend.

The app's older, generic "Challenges" feature (`challenges.html`, a separate page that only ever supported Wordle) has been retired now that Challenge a Friend covers the same ground natively — `words-wordle.js` (its static answer list, `WORDLE_ANSWERS`/`getDailyWordleWord`) was deleted along with it since nothing else used it; the Daily Challenge tab's word pool is entirely Firestore-backed via `wordle-daily-data.js`.

## Points

- **Daily Challenge**: `10` (playing, always) `+ [10,9,8,7,6,5][attempts-1]` (win only, by attempt count) `+ (≤180s:10 / ≤300s:8 / ≤600s:6 / else:5)` (win only, by elapsed time) `+ 20` (Facebook share, either outcome, one-time).
- **Tournaments**: nothing until the run is fully completed — `30` (starting) `+ 15 × numWords` (per-word wins) `+ bonusPoints` (admin-set per tournament), awarded in one shot on completion. Failing any word mid-run resets progress to word 1 with zero points banked; a permanent `completed` flag on the attempt doc blocks re-earning after a successful full run.
- **Challenge a Friend**: the solver gets `10` (attempting, always) `+ 20` (winning), written by `recordWordleChallengeCompletion()` under `gameType: 'wordle-challenge'`. The **creator** separately gets `+10` per distinct player who attempts their challenge, under `gameType: 'wordle-challenge-creator'` — but this can't be granted by the solver's own write, because every `gameScores` create requires the doc's `userId` to equal the writer's own auth uid (otherwise any signed-in user could inflate anyone else's score at will). Instead, `syncCreatorRewards()` runs from the **creator's own session** whenever they open "My Challenges": it scans their challenges' `completions` subcollections and creates any missing `{creatorUid}_wordle-challenge-creator_{challengeId}_{completerUid}` reward docs, guarded by the same create-once pattern as every other score — so it's safe to call on every visit and can never double-pay. Both the per-challenge loop (`syncCreatorRewards()`) and the per-solver loop inside it (`awardCreatorPointsForChallenge()`) run their iterations in parallel via `Promise.all`, not one at a time — with many challenges and many solvers, a sequential version of this was slow enough to be a real, noticeable delay opening "My Challenges".

All three modes share the same "v1-pragmatic, not fully cheat-proof" philosophy as the rest of this app's points: outcomes are self-reported by the client, and Firestore rules bound *how much* a write can award (deterministic create-only doc IDs, per-gameType score caps) rather than verifying gameplay actually happened server-side.
