# src/js/games/wordle

`wordle.html` has three modes, selected by a tab row: **Daily Challenge**, **Tournaments**, and
**Challenge a Friend** (internally still "wordleChallenges"/`wordle-challenge-data.js` in code and
schema — only the user-facing label changed). All three are live.

## Files

- **`wordle-engine.js`** — the playable game itself, mode-agnostic: `playWordleRound({ container, targetWord, maxGuesses, timeLimitSeconds, roundLabel, validateGuess, onComplete })` builds the board + on-screen/physical keyboard into `container`, handles guess evaluation (two-pass duplicate-letter-safe algorithm), and calls `onComplete({ won, attempts, guessStates, timeTakenSeconds, timedOut })` once. `guessStates` is the per-guess correct/present/absent array for every submitted row, used by `wordle-summary-modal.js` to render the colored-square grid. Always shows a live stats bar with Attempts (submitted guesses / `maxGuesses`, updated after each guess) and Time, same as `sudoku-engine.js`/`wordsearch-engine.js`. `timeLimitSeconds` is optional (Tournament only) — when set, the stats bar counts DOWN and ends the round as a timed-out loss if it hits zero, starting immediately since it's a real time-attack constraint. Without it (Daily Challenge, Challenge a Friend), the stats bar is a pure stopwatch counting UP that doesn't start ticking until the player's first letter keystroke — otherwise page-load/read time before their first move would silently eat into Daily Challenge's speed bonus — and its final value comes back as `timeTakenSeconds`; `wordle-page.js` used to compute this itself via a `Date.now()` diff captured at mount time (which had the exact same "counts load time" problem the engine's own delayed start now fixes), so both Daily Challenge's and Challenge a Friend's `onComplete` handlers now just read it off the callback instead. `validateGuess` is an optional `async (guess) => boolean` -- when set (all three modes pass `wordle-word-validation.js#isRealWord`), every non-target guess is checked before being accepted; the row shows "Checking word…" while awaiting it, input is locked for the duration (`submitting` guard), and the guess is snapshotted before the `await` so an in-flight check can never be applied to a guess the player has since edited, or to a round that ended out from under it (e.g. a tournament timer hitting zero mid-check -- re-checked via `gameOver` right after the `await` resolves). The exact target word always bypasses the check, since the win condition shouldn't depend on the dictionary API recognizing whatever word an admin/creator picked. The engine itself has no opinion on *how* validation decides and no Firebase/session knowledge at all — shared by all three of `wordle.html`'s own modes.
- **`wordle-word-validation.js`** — `isRealWord(word)`, checked against `config/wordValidationAPI.endpoint` (the Free Dictionary API `v2`, **not** `v1` — `v1` returns `502` instead of `404` for a nonexistent word, making "not a real word" indistinguishable from "the API is down"). Fails *open*: any non-404 response, a timeout (5s, via `AbortSignal.timeout`), or a network error all count as valid, so a flaky third party can never fully block either playing or creating a challenge. Used at Challenge a Friend creation time (`wordle-challenge-data.js#createWordleChallenge()`) and live during play via the engine's `validateGuess` above -- kept in its own file since it's no longer just a challenge-creation concern. Not wired into Daily Words or Tournament word entry in the admin panel.
- **`wordle-page.js`** — page glue for `wordle.html`: `trySession()` (not `initShell()` -- see `src/js/CLAUDE.md`; renders a static "Sign In to Play" prompt into `#game-mount` instead of redirecting away when there's no session, so `/wordle` itself stays a real, crawlable page, with `wordle.html`'s own static "How to Play" block always visible either way), blocks admins from playing, then wires the three mode tabs (`wireModeTabs`). `wireModeTabs()` owns a single `activeRound` handle (via a `setActiveRound` callback threaded into every mode-render function down to the `playWordleRound(...)` call that mounts it) and calls `activeRound?.destroy()` at the start of every tab switch — without this, switching tabs mid-round left the abandoned round's `document`-level keydown listener alive, so its keystrokes (and eventual stale `onComplete`, popping that round's own summary modal) could fire on top of whatever mode was switched to. **Daily Challenge** (`renderDailyMode`) gates on `checkPlayedToday(uid, 'wordle')`, resolves today's word via `wordle-daily-data.js#getTodayChallenge()`, mounts the engine, and on completion calls `recordDailyResult()` then shows `wordle-summary-modal.js`. **Tournaments** (`renderTournamentsMode` / `playTournamentRound`) lists active tournaments with each one's Start/Continue/Completed status, plays the player's current word with a countdown, and on a loss resets progress and offers a retry; on the final word's win it calls `finalizeTournament()` and shows the summary modal, with one breakdown line per word built from the returned `wordAttempts` array (e.g. "Word 2: solved in 3/6") instead of a single combined "N words solved" line — and never passes `guessStates`, so the modal never shows the colored attempt grid for Tournament, only the per-word/points breakdown. `shareTextForTournament()` mirrors the same per-word list (one "Word N - attempts/6" line per word, dynamic to however many words the tournament has) in the copyable share text instead of a rank line, and links to `/wordle?tab=tournaments` (the shared `TOURNAMENTS_TAB_URL` constant) — `init()` reads that query param and opens straight into the Tournaments tab (the same deep-link mechanism as `?challenge={id}` below, just for a whole tab instead of one specific challenge). Tournament's and Challenge's modal calls both pass `shareLink` explicitly (`TOURNAMENTS_TAB_URL` and `shareLinkForChallenge(challengeId)` respectively) instead of relying on `wordle-summary-modal.js`'s default (`window.location.href`) -- Tournament's page URL never reflects a tab switch, so the default would be flatly wrong there, and while Challenge's current URL happens to already equal `shareLinkForChallenge()` (the solve view is only reachable via that exact `/wordle?challenge={id}` deep link), passing it explicitly avoids depending on that coincidence. Only Daily still relies on the default, since its own page IS the canonical link. **Challenge a Friend** (`renderChallengeMode` and friends) has three sub-tabs — Browse (public, non-expired, excluding your own, paginated `config/browseChallengesPageSize.size` at a time via "Load More" -- if a fetched page comes back entirely filtered out, `loadPage()` silently fetches the next one instead of showing an empty page with nothing on it), Create (registered users only; 5-letter word, checked against `config/wordValidationAPI` for being a real word — see `wordle-word-validation.js#isRealWord()` — plus public/private visibility, produces a `/wordle?challenge={id}` share link), My Challenges (your own challenges as compact cards -- `#N`, word, creation date, attempt count, visibility -- paginated `config/myChallengesPageSize.size` at a time; opening this view also runs `syncCreatorRewards()` over *all* of your challenges regardless of how many are currently paginated in, see below). Both the Create result and each My Challenges card's share-link box show a Copy button (`wireCopyLink()`, always present) plus a Share button (`wireShareLink()`/`shareButtonHtml()`) -- the Share button is only rendered when `navigator.share` exists (feature-detected at render time, not hidden via CSS), since `shareUrl()`'s non-native fallback opens a Facebook popup rather than copying to the clipboard, which would be a worse experience than the copy button already sitting right next to it; both buttons send the same `challengeShareText(link)` message (a fixed template: "🟪 I've got a Wordle challenge for you!" intro, the link, "Can you beat the challenge? 🔥" outro). Each My Challenges card's "More Info" button (`wireMineDetailToggle()`) lazily expands into a detail panel -- nothing about that challenge's attempts is fetched until the card is actually opened -- with the share-link box and an Attempts table (`#`, user, `attempts/6`, Solved/Failed pill), itself paginated `config/challengeAttemptsPageSize.size` at a time via its own "Load More". Toggling the card closed and back open again doesn't re-fetch. Plus a deep-link path: loading `/wordle?challenge={id}` jumps straight to solving that one challenge instead of showing the sub-tabs, so a shared link works standalone.
- **`wordle-daily-data.js`** — Firestore layer for Daily Challenge: `getTodayChallenge()` (resolves today's word via a direct date lookup, not a formula -- each `wordleDailyWords` doc is keyed by the exact "YYYY-MM-DD" date it plays on, set once when it's added by `src/js/admin/wordle-admin.js#addDailyWord()`, so adding more words later never recomputes or shifts which date any existing word lands on. Before `_meta.firstDate` -- i.e. before launch -- always resolves to Challenge #1, so the Daily Challenge can be previewed ahead of the real launch date without faking the system clock; this fallback does NOT apply once the calendar's actually running, so a seeded pool running dry still correctly shows "not ready yet" instead of silently repeating #1 forever), `recordDailyResult()` (writes the points formula below to `gameScores` with the existing `{uid}_wordle_{date}` deterministic ID, so a repeat attempt is rejected the same way every other game's score is), `markSharedToFacebook()` (one-time guarded +20 on the `sharedToFacebook` field) and `markSharedWithFriends()` (one-time guarded +10 on a separate `sharedWithFriends` field) — two independent, stackable share bonuses, each applied as its own Firestore `update` after the score doc already exists — see `firestore.rules`' `isCommunityShareUpdate()`/`isFriendsShareUpdate()`, which independently bound each field's own delta.
- **`wordle-tournament-data.js`** — Firestore layer for Tournaments: `listActiveTournaments()`, `getAttempt()` / `getOrStartAttempt()` (one progress doc per player per tournament, id `{tournamentId}_{uid}`, created at word 1 on first play, with `wordAttempts: []`), `recordWordResult(tournamentId, uid, won, attempts)` (advances `currentWordIndex`/`wordsWon` and appends `attempts` to `wordAttempts` on a win, resets `currentWordIndex`/`wordsWon`/`wordAttempts` on a loss — players can retry a failed tournament indefinitely, but a failed run banks nothing), `finalizeTournament()` (one-shot award of `30 + 15*numWords + bonusPoints` to `gameScores` under `gameType: 'wordle-tournament'` with a deterministic `{uid}_wordle-tournament_{tournamentId}` id — the same create-only guarantee as every other game score means this can never double-pay even if called twice — reads the attempt doc's `wordAttempts` into the written score doc for the completion modal's per-word breakdown, then flips the attempt's `completed` flag permanently), and `markSharedToFacebook()`/`markSharedWithFriends()` (see Points below).
- **`wordle-challenge-data.js`** — Firestore layer for Challenge a Friend, in the `wordleChallenges` collection (`{ creatorUid, creatorDisplayName, word, visibility, challengeNumber, createdAt, expiresAt }`, with a `completions/{uid}` subcollection per challenge). `challengeNumber` is a global, continuously-incrementing counter (not per-creator, so "Oshini's Challenge #1"/"#2" are distinguishable even with duplicate creator names) tracked in `wordleChallenges/_meta.totalCount` and bumped inside the same transaction that creates the challenge — same pattern as the Daily Challenge word pool, just writable by any registered user instead of admin-only. `createWordleChallenge()` (registered users only; expiry reuses `config/challengeExpiration`; the word must pass `isRealWord()`, a dictionary check against `config/wordValidationAPI.endpoint` that fails open on any API error so a flaky third party can't block challenge creation entirely), `listPublicWordleChallengesPage(pageSize, cursor)` / `listMyWordleChallengesPage(uid, pageSize, cursor)` (both cursored via `startAfter`, for rendering Browse/My Challenges a page at a time -- reuse the existing `(visibility, createdAt)` / `(creatorUid, createdAt)` composite indexes, no new indexes needed), `listWordleChallengeCompletionsPage(challengeId, pageSize, cursor)` (cursored via `startAfter` on `completedAt`, for one challenge's Attempts table -- only needs Firestore's automatic single-field index, no composite), `listMyWordleChallenges(uid)` (unpaginated, for `syncCreatorRewards()` only), `getWordleChallenge()` / `getWordleChallengeCompletion()` / `getWordleChallengeSolveCount()` (a `getCountFromServer` aggregation query counting only `won == true` — Browse cards show "N people solved it") / `getWordleChallengeAttemptCount()` (same aggregation shape but no `won` filter — My Challenges cards show "N Attempts"), `recordWordleChallengeCompletion()` (player's own `10 + 20-if-won` score), `syncCreatorRewards()` (see Points below for why this is separate), and `markSharedToFacebook()`/`markSharedWithFriends()` (see Points below).
- **`wordle-summary-modal.js`** — shared post-round popup (points breakdown, colored-square attempt grid built from `guessStates` when provided — always rendered as a fixed 6-row grid, with rows beyond what was actually played shown as empty placeholders rather than the grid shrinking to match the attempt count). An optional `celebrate` flag shows a trophy-in-a-circle + confetti header above the title (Daily Challenge and Challenge a Friend pass this on a win only; Tournament always does, since reaching this screen at all means the run is complete). All three modes also pass `shareText`/`communityUrl`/`onShareCommunity`/`onShareFriends`, rendering the same two independent share options (+20 community, +10 friends — see Points below) with mode-specific share text built by each mode's own `shareTextForX()` helper in `wordle-page.js`. Builds its own DOM into `document.body`; no markup for it lives in `wordle.html` itself.

The app's older, generic "Challenges" feature (`challenges.html`, a separate page that only ever supported Wordle) has been retired now that Challenge a Friend covers the same ground natively — `words-wordle.js` (its static answer list, `WORDLE_ANSWERS`/`getDailyWordleWord`) was deleted along with it since nothing else used it; the Daily Challenge tab's word pool is entirely Firestore-backed via `wordle-daily-data.js`.

## Points

- **Daily Challenge**: `10` (playing, always) `+ [10,9,8,7,6,5][attempts-1]` (win only, by attempt count) `+ (≤180s:10 / ≤300s:8 / ≤600s:6 / else:5)` (win only, by elapsed time) `+ 20` **and/or** `+10` (either outcome, two independent one-time bonuses, both claimable — "Copy Result & Share with Community" copies the result text to the clipboard and opens `FACEBOOK_GROUP_URL` for +20 via `markSharedToFacebook()`, "Share with Friends" uses the native Web Share API for +10 via `markSharedWithFriends()`; using an option again after its own bonus is claimed still performs the share action, just without re-awarding points).
- **Tournaments**: nothing until the run is fully completed — `30` (starting) `+ 15 × numWords` (per-word wins) `+ bonusPoints` (admin-set per tournament), awarded in one shot on completion. Failing any word mid-run resets progress to word 1 with zero points banked; a permanent `completed` flag on the attempt doc blocks re-earning after a successful full run. Plus `+20` and/or `+10` for sharing (see below).
- **Challenge a Friend**: the solver gets `10` (attempting, always) `+ 20` (winning), written by `recordWordleChallengeCompletion()` under `gameType: 'wordle-challenge'`. The **creator** separately gets `+10` per distinct player who attempts their challenge, under `gameType: 'wordle-challenge-creator'` — but this can't be granted by the solver's own write, because every `gameScores` create requires the doc's `userId` to equal the writer's own auth uid (otherwise any signed-in user could inflate anyone else's score at will). Instead, `syncCreatorRewards()` runs from the **creator's own session** whenever they open "My Challenges": it scans their challenges' `completions` subcollections and creates any missing `{creatorUid}_wordle-challenge-creator_{challengeId}_{completerUid}` reward docs, guarded by the same create-once pattern as every other score — so it's safe to call on every visit and can never double-pay. Both the per-challenge loop (`syncCreatorRewards()`) and the per-solver loop inside it (`awardCreatorPointsForChallenge()`) run their iterations in parallel via `Promise.all`, not one at a time — with many challenges and many solvers, a sequential version of this was slow enough to be a real, noticeable delay opening "My Challenges". Plus `+20` and/or `+10` for sharing (see below).
- **Sharing** (Daily Challenge, Tournaments, and Challenge a Friend alike): `+20` for "Copy Result & Share with Community" (`markSharedToFacebook()` on that mode's own `gameScores` doc) and `+10` for "Share with Friends" (`markSharedWithFriends()`) — two independent, one-time, **stackable** bonuses, not alternatives; a player can claim both. Each mode's data file (`wordle-daily-data.js`, `wordle-tournament-data.js`, `wordle-challenge-data.js`) has its own copy of these two functions, scoped to its own doc-ID scheme, guarded by its own `sharedToFacebook`/`sharedWithFriends` fields on that doc. `firestore.rules`' `isCommunityShareUpdate()`/`isFriendsShareUpdate()` independently bound each field's own delta across all three gameTypes. Since Phase 3 of `docs/progression-gamification-roadmap.md`, each of these six functions also calls `progression/xp-service.js#awardShareXp()` (a small flat global-XP bump, registered players only) right after its own Points transaction, only when the bonus was newly applied.

**XP** (Phase 3, registered players only, separate from the Points above): Daily Challenge completion additionally awards `progression/xp-service.js#XP_AMOUNTS.DAILY_GAME_COMPLETION` (called from `wordle-page.js` after `recordDailyResult()` succeeds), plus a one-time `PERFECT_DAY_BONUS` if that was the last of today's Daily Challenges across all games (checked via `utils/points.js#checkPlayedTodayAll()`). Tournament and Challenge a Friend don't award their own completion XP — only the share bonuses above apply to those modes.

**Streak** (Phase 4, registered players only): the same Daily Challenge completion call site also calls `progression/streak-service.js#advanceStreakForDailyCompletion()`, right alongside the XP call. Tournament/Challenge a Friend don't advance the streak — only an actual Daily Challenge completion (any of the three games) does.

All three modes share the same "v1-pragmatic, not fully cheat-proof" philosophy as the rest of this app's points: outcomes are self-reported by the client, and Firestore rules bound *how much* a write can award (deterministic create-only doc IDs, per-gameType score caps) rather than verifying gameplay actually happened server-side.
