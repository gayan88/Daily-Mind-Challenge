# src/js/games/wordle

`wordle.html` has three modes, selected by a tab row: **Daily Challenge**, **Tournaments**, and
**Challenge a Friend** (internally still "wordleChallenges"/`wordle-challenge-data.js` in code and
schema — only the user-facing label changed). All three are live.

## Files

- **`wordle-engine.js`** — the playable game itself, mode-agnostic: `playWordleRound({ container, targetWord, maxGuesses, timeLimitSeconds, onComplete })` builds the board + on-screen/physical keyboard into `container`, handles guess evaluation (two-pass duplicate-letter-safe algorithm), and calls `onComplete({ won, attempts, guessStates, timedOut })` once. `guessStates` is the per-guess correct/present/absent array for every submitted row, used by `wordle-summary-modal.js` to render the colored-square grid. `timeLimitSeconds` is optional — when set, shows a visible countdown and ends the round as a timed-out loss if it hits zero (used by Tournament mode). No Firebase/session knowledge at all — this file is also reused as-is by `src/js/pages/challenges.js` for the existing, separate generic challenge feature (a different target word, same engine); that caller only destructures `{ won, attempts }`, so the added fields are inert to it.
- **`wordle-page.js`** — page glue for `wordle.html`: `initShell()`, blocks admins from playing, then wires the three mode tabs (`wireModeTabs`). **Daily Challenge** (`renderDailyMode`) gates on `checkPlayedToday(uid, 'wordle')`, resolves today's word via `wordle-daily-data.js#getTodayChallenge()`, mounts the engine, and on completion calls `recordDailyResult()` then shows `wordle-summary-modal.js`. **Tournaments** (`renderTournamentsMode` / `playTournamentRound`) lists active tournaments with each one's Start/Continue/Completed status, plays the player's current word with a countdown, and on a loss resets progress and offers a retry; on the final word's win it calls `finalizeTournament()` and shows the summary modal. **Challenge a Friend** (`renderChallengeMode` and friends) has three sub-tabs — Browse (public, non-expired, excluding your own), Create (registered users only; 5-letter word + public/private visibility, produces a `wordle.html?challenge={id}` share link), My Challenges (your own challenges with each one's completions list; opening this view also runs `syncCreatorRewards()`, see below) — plus a deep-link path: loading `wordle.html?challenge={id}` jumps straight to solving that one challenge instead of showing the sub-tabs, so a shared link works standalone.
- **`wordle-daily-data.js`** — Firestore layer for Daily Challenge: `getTodayChallenge()` (resolves the numbered word for today, `(daysSinceEpoch(date) % totalCount) + 1`, from the admin-managed `wordleDailyWords` collection — see `src/js/admin/wordle-admin.js`), `recordDailyResult()` (writes the points formula below to `gameScores` with the existing `{uid}_wordle_{date}` deterministic ID, so a repeat attempt is rejected the same way every other game's score is), `markSharedToFacebook()` (one-time guarded +20, applied as a Firestore `update` after the score doc already exists — see `firestore.rules`' `isFacebookShareUpdate()`).
- **`wordle-tournament-data.js`** — Firestore layer for Tournaments: `listActiveTournaments()`, `getAttempt()` / `getOrStartAttempt()` (one progress doc per player per tournament, id `{tournamentId}_{uid}`, created at word 1 on first play), `recordWordResult(tournamentId, uid, won)` (advances `currentWordIndex`/`wordsWon` on a win, resets both to 0 on a loss — players can retry a failed tournament indefinitely, but a failed run banks nothing), `finalizeTournament()` (one-shot award of `30 + 15*numWords + bonusPoints` to `gameScores` under `gameType: 'wordle-tournament'` with a deterministic `{uid}_wordle-tournament_{tournamentId}` id — the same create-only guarantee as every other game score means this can never double-pay even if called twice — then flips the attempt's `completed` flag permanently).
- **`wordle-challenge-data.js`** — Firestore layer for Challenge a Friend, in the `wordleChallenges` collection (`{ creatorUid, creatorDisplayName, word, visibility, createdAt, expiresAt }`, with a `completions/{uid}` subcollection per challenge — same shape as the existing generic `challenges` collection, kept as a separate collection per the revamp plan rather than reusing it). `createWordleChallenge()` (registered users only; expiry reuses `config/challengeExpiration`), `listPublicWordleChallenges()` / `listMyWordleChallenges(uid)`, `getWordleChallenge()` / `getWordleChallengeCompletion()` / `listWordleChallengeCompletions()`, `recordWordleChallengeCompletion()` (player's own `10 + 20-if-won` score), and `syncCreatorRewards()` (see Points below for why this is separate).
- **`wordle-summary-modal.js`** — shared post-round popup (points breakdown, colored-square attempt grid built from `guessStates` when provided, Facebook share button using the same `sharer.php` popup pattern as the footer share in `src/js/app.js`). Builds its own DOM into `document.body`; no markup for it lives in `wordle.html` itself. Used by Daily Challenge, Tournaments, and Challenge a Friend.
- **`words-wordle.js`** — the original static answer list (`WORDLE_ANSWERS`) and `getDailyWordleWord(dateString)`. **No longer used by the Daily Challenge tab** (superseded by `wordle-daily-data.js`'s Firestore-backed word pool) — still used by `src/js/pages/challenges.js` for its "pick a word" dropdown, which is untouched by this revamp.

## Points

- **Daily Challenge**: `10` (playing, always) `+ [10,9,8,7,6,5][attempts-1]` (win only, by attempt count) `+ (≤180s:10 / ≤300s:8 / ≤600s:6 / else:5)` (win only, by elapsed time) `+ 20` (Facebook share, either outcome, one-time).
- **Tournaments**: nothing until the run is fully completed — `30` (starting) `+ 15 × numWords` (per-word wins) `+ bonusPoints` (admin-set per tournament), awarded in one shot on completion. Failing any word mid-run resets progress to word 1 with zero points banked; a permanent `completed` flag on the attempt doc blocks re-earning after a successful full run.
- **Challenge a Friend**: the solver gets `10` (attempting, always) `+ 20` (winning), written by `recordWordleChallengeCompletion()` under `gameType: 'wordle-challenge'`. The **creator** separately gets `+10` per distinct player who attempts their challenge, under `gameType: 'wordle-challenge-creator'` — but this can't be granted by the solver's own write, because every `gameScores` create requires the doc's `userId` to equal the writer's own auth uid (otherwise any signed-in user could inflate anyone else's score at will). Instead, `syncCreatorRewards()` runs from the **creator's own session** whenever they open "My Challenges": it scans their challenges' `completions` subcollections and creates any missing `{creatorUid}_wordle-challenge-creator_{challengeId}_{completerUid}` reward docs, guarded by the same create-once pattern as every other score — so it's safe to call on every visit and can never double-pay.

All three modes share the same "v1-pragmatic, not fully cheat-proof" philosophy as the rest of this app's points: outcomes are self-reported by the client, and Firestore rules bound *how much* a write can award (deterministic create-only doc IDs, per-gameType score caps) rather than verifying gameplay actually happened server-side.
