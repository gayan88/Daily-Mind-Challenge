# src/js/games/wordsearch

`wordsearch.html` has three modes, selected by a tab row: **Daily Challenge**, **Classic**, and
**Tournament**. All three are live.

## Files

- **`wordsearch-engine.js`** — the playable grid itself, mode-agnostic: `playWordSearchRound({ container, words, seed, gridSize, directions, timeLimitSeconds, onComplete })`. Generates a grid at runtime via a seeded `mulberry32(seed)` PRNG (`src/js/utils/helpers.js`) — words are placed by trying up to 400 random `(direction, row, col)` attempts, then a deterministic exhaustive fallback that guarantees placement whenever geometrically possible. `directions` (an array of `[dr,dc]` vectors — see `DIRECTIONS_2WAY`/`DIRECTIONS_8WAY`, both exported) controls where words get *placed*, not how a player is allowed to *find* them: selection is mouse/touch drag constrained to straight lines, and matching checks both the forward and reversed letter string against the remaining word set, so a word placed in only 2 directions can still be dragged either way along that axis. Always shows a live stats bar (Words Found + Time), like `sudoku-engine.js`. `timeLimitSeconds` is optional (Tournament only) — when set, the stats bar counts down and hitting zero ends the round as a loss (`timedOut: true`) with the un-found words revealed (`.ws-cell.revealed`/`.ws-word.revealed`), using cell positions captured during placement (`generateGrid` returns a `placements` map alongside the grid). Calls `onComplete({ won, wordsFound, totalWords, timeTakenSeconds, timedOut })` exactly once. Returns `{ destroy }` which actually removes its `window`-level mouseup listener — this matters because Tournament mounts/unmounts rounds repeatedly within one page session.
- **`wordsearch-modes.js`** — pure constants (no Firebase import): `DAILY_MODE`, `TOURNAMENT_MODE` (both `{ gridSize: 12, wordCount: 10, directions: DIRECTIONS_8WAY }`), `CLASSIC_MODES.easy/medium/hard` (`10×10`/6 words/2-way, `12×12`/10 words/8-way, `15×15`/10 words/8-way respectively), and `WORD_MIN_LENGTH`/`WORD_MAX_LENGTH` (4/9). Single source of truth shared by `wordsearch-page.js` (mounting the engine) and `src/js/admin/wordsearch-admin.js` (validating word lists an admin enters) so the numbers can't drift between the two.
- **`wordsearch-page.js`** — page glue for `wordsearch.html`: `initShell()`, blocks admins, then wires the three mode tabs (`wireModeTabs`), which owns one `activeRound` handle so switching tabs mid-round always calls the previous round's `destroy()` first. **Daily Challenge** (`renderDailyMode`) gates on `checkPlayedToday(uid, 'wordsearch')`, resolves today's puzzle via `wordsearch-daily-data.js#getTodayChallenge()`, mounts the engine with no time limit, and on completion calls `recordDailyResult()` then shows `wordsearch-summary-modal.js`. **Classic** (`renderClassicMode` / `renderDifficultyPicker` / `playClassicRound`) has no gate — pick Easy/Medium/Hard, get a random puzzle from that difficulty's pool via `wordsearch-classic-data.js#getRandomClassicPuzzle()`, grid seed is a **fresh random number each round** (not derived from the puzzle's id, so replaying the same word list doesn't render an identical, memorizable grid), and the summary modal's "Close" returns to the difficulty picker. **Tournament** (`renderTournamentMode` / `playWordsearchTournamentRound` / `finishWordsearchTournament`) lists active tournaments with Start/Continue/Completed status, plays the player's current puzzle under the global `config/wordsearchTournamentSettings` time limit, and — like Sudoku Tournament, unlike Wordle Tournament — a failed puzzle does **not** reset progress: it banks the failed-puzzle points immediately and the player moves straight to the next puzzle with a fresh timer (a short inline pass/fail message, not the summary modal, appears between puzzles). A **live running score** is shown during play (`attempt.puzzlesPassed * settings.completedPoints + attempt.puzzlesFailed * settings.failedPoints`, recomputed from the attempt doc's own counters — no dedicated schema field, and correct even after resuming a reloaded page mid-run) — this is the one display element Word Search Tournament has that Sudoku Tournament doesn't (Sudoku only shows the running total at the very end). Once every puzzle has been attempted, `finishWordsearchTournament()` awards the one-time completion bonus and shows the summary modal for the whole run.
- **`wordsearch-daily-data.js`** — Firestore layer for Daily Challenge: `getTodayChallenge()` (resolves the numbered puzzle for today, `(daysSinceEpoch(date) % totalCount) + 1`, from the admin-managed `wordsearchDailyPuzzles` collection — see `src/js/admin/wordsearch-admin.js`), `recordDailyResult()` (writes the points formula below to `gameScores` with the pre-existing `{uid}_wordsearch_{date}` deterministic ID — unchanged from this app's original single-mode Word Search, so `checkPlayedTodayAll()`'s hardcoded `{wordle, sudoku, wordsearch}` shape and the home page's "completed today" tile badge needed zero changes for this revamp). Also exports `timeBonus()` — Word Search's own 5min/10min tiers, distinct from Sudoku's 10min/20min ones — which Classic reuses rather than duplicating.
- **`wordsearch-classic-data.js`** — Firestore layer for Classic: `getRandomClassicPuzzle(difficulty)` (queries `wordsearchClassicPuzzles` by `difficulty`, picks one client-side), `recordClassicResult()` (completion points by difficulty — `{easy:10, medium:15, hard:25}` — plus the shared time bonus). Classic allows unlimited scored replays per day, so each round gets its own client-generated unique `gameScores` doc ID (`doc(collection(db,'gameScores')).id`, repurposing `gameDate` as an arbitrary unique token) — same pattern as `wordsearch-tournament`/Sudoku Classic.
- **`wordsearch-tournament-data.js`** — Firestore layer for Tournament: `listActiveWordsearchTournaments()`, `getAttempt()` / `getOrStartAttempt()` (one progress doc per player per tournament, id `{tournamentId}_{uid}`), `recordPuzzleResult(tournament, uid, profile, { puzzleIndex, passed, completedPoints, failedPoints })` (banks points **and** advances the attempt's progress in a single `runTransaction`, idempotent against a client-level retry via a `currentPuzzleIndex` check — see `sudoku-tournament-data.js` for the identical pattern). Unlike Sudoku, `completedPoints`/`failedPoints` are **parameters** here (sourced from `config/wordsearchTournamentSettings`), not hardcoded — Word Search Tournament makes its per-puzzle points admin-configurable, a deliberate divergence from Sudoku Tournament's fixed 50/10. `completeTournamentIfNeeded(uid, profile, tournament)` — one-shot completion bonus (`tournament.completionBonus`, set per tournament at creation, not global), wrapped in a single transaction with marking `completed`/`bonusAwarded` so it's safely re-callable.
- **`wordsearch-summary-modal.js`** — shared post-round popup for Daily and Classic (points breakdown + Facebook share button) and, once per run, for Tournament's final summary. No colored-guess-grid visualization since Word Search has no per-guess history to render.
- **`wordsearch-words.js`** — the original static bank of 20 `{ theme, words }` entries, kept in place but no longer referenced by any live code. Left as a copy-paste source an admin can use when seeding `wordsearchDailyPuzzles`/`wordsearchClassicPuzzles` via the admin panel.

## Firestore schema

- **`wordsearchDailyPuzzles/{id}`** (`id` = "1", "2", ...) + **`_meta`** (`{ totalCount }`) — admin-managed, append-only. Puzzle docs hold `{ theme (optional), words }` — the grid itself is generated at play time, not admin-authored like Sudoku's puzzle+solution pairs.
- **`wordsearchClassicPuzzles/{id}`** (one global numeric id sequence shared across all three difficulties) + `_meta` — `{ theme (optional), words, difficulty }`.
- **`wordsearchTournaments/{autoId}`** — `{ name, puzzles: [{ words }, ...], completionBonus, active, createdAt }`. Puzzle count, time limit, and completed/failed puzzle points come from `config/wordsearchTournamentSettings` instead — a tournament's own `puzzles.length` drives its completion check, not the global `puzzleCount` field, so changing that setting later never breaks an already-created tournament.
- **`wordsearchTournamentAttempts/{tournamentId}_{uid}`** — `{ uid, displayName, tournamentId, currentPuzzleIndex, puzzlesPassed, puzzlesFailed, startedAt, completed, completedAt, bonusAwarded }`. Exactly one attempt per player per tournament, ever — byte-for-byte the same bounded-progression shape as `sudokuTournamentAttempts` (`completed` only flips false→true, the three counters only hold steady or advance by exactly 1, nothing ever resets since a failed puzzle only ends that puzzle).

## Points

- **Daily Challenge**: `25` (completing) `+ timeBonus(timeTakenSeconds)` `+ 20` (Facebook share, one-time). `timeBonus`: `<300s(5min):25 / <600s(10min):15 / else:10`. Max pre-share: 70.
- **Classic**: `{easy:10, medium:15, hard:25}` (completing) `+ timeBonus + 20` (share). Same bonus tiers as Daily. Max pre-share: 70 (hard).
- **Tournament**: per puzzle, banked immediately — `config/wordsearchTournamentSettings.completedPoints` (default 50) if passed, `.failedPoints` (default 10) if the timer runs out. Plus a one-time `tournament.completionBonus` (admin-set per tournament, default suggestion 250) once every puzzle has been attempted.

Unlike Sudoku/Wordle, there is **no error/accuracy bonus component anywhere** — Word Search has no "wrong answer" concept (a drag either matches a remaining word or it doesn't), so every formula here is just completion + time (+ share). Daily and Classic only score on actual completion — no partial credit for an abandoned round.

All three modes share the app's "v1-pragmatic, not fully cheat-proof" points philosophy: outcomes are self-reported by the client, and `firestore.rules` bounds *how much* a write can award (deterministic create-only doc IDs, per-gameType score caps via `maxCreateScore()`) rather than verifying gameplay actually happened server-side.
