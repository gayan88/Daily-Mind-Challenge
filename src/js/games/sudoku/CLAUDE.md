# src/js/games/sudoku

`sudoku.html` has three modes, selected by a tab row: **Daily Challenge**, **Classic Sudoku**, and
**Tournament**. All three are live.

## Files

- **`sudoku-engine.js`** — the playable grid itself, mode-agnostic: `playSudokuRound({ container, puzzle, solution, timeLimitSeconds, maxErrors, onComplete })`. Tap-a-cell-then-tap-a-number entry (mobile-friendly, avoids raw `<input>` zoom/keyboard issues). Correctness is checked by direct string comparison against the known `solution` — there's no general constraint-solving/validation engine. Always shows a live stats bar (time + errors), unlike Wordle's timer which only appears when a limit is set — all three Sudoku modes display this per spec. `timeLimitSeconds`/`maxErrors` are optional (Tournament only): when set, the stats bar counts down instead of up, and hitting either limit ends the round as a loss (`timedOut: true` on a timeout). On a loss the solution is revealed in every non-given cell, with mismatched cells marked `.revealed`. Calls `onComplete({ won, errors, timeTakenSeconds, timedOut })` exactly once. Returns `{ destroy }` to stop its internal timer — callers that might replace the container mid-round (e.g. a mode-tab switch) must call this, or the interval keeps ticking against a detached DOM element forever.
- **`sudoku-page.js`** — page glue for `sudoku.html`: `initShell()`, blocks admins from playing, then wires the three mode tabs (`wireModeTabs`), which owns one `activeRound` handle (via `setActiveRound`) so switching tabs mid-round always calls the previous round's `destroy()` first. **Daily Challenge** (`renderDailyMode`) gates on `checkPlayedToday(uid, 'sudoku')`, resolves today's puzzle via `sudoku-daily-data.js#getTodayChallenge()`, mounts the engine with no time/error limit, and on completion calls `recordDailyResult()` then shows `sudoku-summary-modal.js`. **Classic Sudoku** (`renderClassicMode` / `renderDifficultyPicker` / `playClassicRound`) has no played-today gate — pick Easy/Medium/Hard, get a random puzzle from that difficulty's pool via `sudoku-classic-data.js#getRandomClassicPuzzle()`, and the summary modal's "Close" returns to the difficulty picker so replaying is a one-click loop. **Tournament** (`renderTournamentMode` / `playSudokuTournamentRound` / `finishSudokuTournament`) lists active tournaments with each one's Start/Continue/Completed status, plays the player's current puzzle under the global `config/sudokuTournamentSettings` time limit and max errors, and — unlike Wordle Tournament — a failed puzzle does **not** reset progress: it banks 10 points immediately and the player moves straight to the next puzzle with a fresh timer/error count (a short inline pass/fail message, not the summary modal, appears between puzzles). Once every puzzle has been attempted, `finishSudokuTournament()` awards the one-time completion bonus and shows the summary modal for the whole run.
- **`sudoku-daily-data.js`** — Firestore layer for Daily Challenge: `getTodayChallenge()` (resolves the numbered puzzle for today, `(daysSinceEpoch(date) % totalCount) + 1`, from the admin-managed `sudokuDailyPuzzles` collection — see `src/js/admin/sudoku-admin.js`), `recordDailyResult()` (writes the points formula below to `gameScores` with the pre-existing `{uid}_sudoku_{date}` deterministic ID — unchanged from this app's original single-mode Sudoku, so `checkPlayedTodayAll()`'s hardcoded `{wordle, sudoku, wordsearch}` shape and the home page's "completed today" tile badge needed zero changes for this revamp). Also exports `timeBonus()`/`errorBonus()`, the two shared bonus-tier helpers Classic Sudoku reuses rather than duplicating (they're defined identically for both modes per spec).
- **`sudoku-classic-data.js`** — Firestore layer for Classic Sudoku: `getRandomClassicPuzzle(difficulty)` (queries `sudokuClassicPuzzles` by `difficulty`, picks one client-side — no "today's puzzle" concept here), `recordClassicResult()` (completion points by difficulty — `{easy:10, medium:15, hard:25}` — plus the same time/error bonuses as Daily). Classic allows unlimited scored replays per day, which the Daily doc-ID scheme can't support, so each round gets its own client-generated unique `gameScores` doc ID (`doc(collection(db,'gameScores')).id`, repurposing the `gameDate` field as an arbitrary unique token rather than a calendar date) — same pattern as `wordle-challenge`/`wordle-tournament`.
- **`sudoku-tournament-data.js`** — Firestore layer for Tournament: `listActiveSudokuTournaments()`, `getAttempt()` / `getOrStartAttempt()` (one progress doc per player per tournament, id `{tournamentId}_{uid}`, created at puzzle 1 on first play — resuming an unfinished attempt is just fetching this same doc), `recordPuzzleResult(tournament, uid, profile, { puzzleIndex, passed })` (banks 50/10 points **and** advances `currentPuzzleIndex`/`puzzlesPassed`/`puzzlesFailed` in a single `runTransaction`, so a browser closing mid-write can never lose a puzzle's points or leave the attempt doc out of sync with what was actually scored — stronger atomicity than Wordle Tournament needs, because a Sudoku puzzle failure doesn't reset progress the way a Wordle word failure does. Also idempotent against a client-level retry: if `currentPuzzleIndex` has already moved past the puzzle being recorded, it's a no-op read rather than a double-score), `completeTournamentIfNeeded(uid, profile, tournament, settings)` (one-shot completion bonus, wrapped in the same kind of single transaction as the bonus write + `completed`/`bonusAwarded` flags together — safely re-callable any time an attempt is revisited with `bonusAwarded` still false, e.g. after a dropped connection right after the last puzzle).
- **`sudoku-summary-modal.js`** — shared post-round popup for Daily and Classic (points breakdown + Facebook share button) and, once per run, for Tournament's final summary. No colored-guess-grid visualization (unlike Wordle's summary modal) since Sudoku has no per-guess history to render. Tournament's per-puzzle pass/fail doesn't use this modal — see `sudoku-page.js` above.
- **`sudoku-puzzles.js`** — the original static bank of 30 `{ puzzle, solution }` pairs, kept in place but no longer referenced by any live code. Left as a ready-made source an admin can copy-paste from when seeding `sudokuDailyPuzzles`/`sudokuClassicPuzzles` via the admin panel.

## Firestore schema

- **`sudokuDailyPuzzles/{id}`** (`id` = "1", "2", ...) + **`sudokuDailyPuzzles/_meta`** (`{ totalCount }`) — admin-managed, append-only (see `src/js/admin/sudoku-admin.js`).
- **`sudokuClassicPuzzles/{id}`** (one global numeric id sequence shared across all three difficulties) + `_meta` — `{ puzzle, solution, difficulty }`.
- **`sudokuTournaments/{autoId}`** — `{ name, puzzles: [{ puzzle, solution }, ...], completionBonus, active, createdAt }`. `completionBonus` is set per tournament at creation time (like Wordle Tournament's `bonusPoints`). Time limit and max errors per puzzle stay global, via `config/sudokuTournamentSettings` (edited through the generic admin config form). A tournament's own `puzzles.length` is what actually drives its completion check, not the global `puzzleCount` field on that same config doc — that field is just a guardrail admins see at creation time, so changing it later never breaks an already-created tournament's progress logic.
- **`sudokuTournamentAttempts/{tournamentId}_{uid}`** — `{ uid, displayName, tournamentId, currentPuzzleIndex, puzzlesPassed, puzzlesFailed, startedAt, completed, completedAt, bonusAwarded }`. Exactly one attempt per player per tournament, ever — `completed` only ever flips false→true (enforced by `firestore.rules`), and none of the three counters ever reset, unlike `wordleTournamentAttempts`'s word-index reset on a loss.

## Points

- **Daily Challenge**: `25` (completing) `+ timeBonus(timeTakenSeconds)` `+ errorBonus(errors)` `+ 20` (Facebook share, one-time). `timeBonus`: `<600s:25 / <1200s:15 / else:10`. `errorBonus`: `≤3:50 / ≤6:40 / ≤9:30 / ≤12:20 / else:10`. Max pre-share: 100.
- **Classic Sudoku**: `{easy:10, medium:15, hard:25}` (completing) `+ timeBonus + errorBonus + 20` (share). Same bonus tiers as Daily. Max pre-share: 100 (hard).
- **Tournament**: per puzzle, banked immediately — `50` if passed, `10` if failed (timeout or exceeding `maxErrors`). Plus a one-time `tournament.completionBonus` (set per tournament by the admin at creation, default suggestion 250) once every puzzle in the tournament has been attempted, regardless of individual pass/fail.

Both Daily and Classic only score on actual completion — there's no "gave up" state, since Sudoku has no inherent turn limit outside Tournament mode.

All three modes share the app's "v1-pragmatic, not fully cheat-proof" points philosophy: outcomes are self-reported by the client, and `firestore.rules` bounds *how much* a write can award (deterministic create-only doc IDs, per-gameType score caps via `maxCreateScore()`) rather than verifying gameplay actually happened server-side.
